# Kleinanzeigen: поиск пользователя + мониторинг объявлений

Курсовая работа: поиск конкретного продавца на kleinanzeigen.de для анализа рынка.
Всё в **одном скрипте** `kleinanzeigen_bot.py` и **одном Telegram-боте**
(раньше это были 4 отдельных скрипта: `1.py`, `2v2.py`, `3neu.py`, `10min.py` + `Osnova.py`).

## Как это работает

```
скрин/текст в бота ──► распознавание ──► «🔍 Искать»
        │
        ▼
1. Поиск диапазона ID за нужный день (бывшие 1.py + 2v2.py)
   • старт — от ближайшей известной пары «ID → дата» (база якорей)
   • прыжки с оценкой «ID в день», которая уточняется по увиденным точкам
   • интерполяционный + бинарный поиск первой и последней границы дня
        │
        ▼
2. Перебор всех ID дня (бывший 3neu.py)
   • сравнение: имя (с учётом ä/ae/a и опечаток OCR), дата, плашки
   • точное совпадение → сразу сообщение в Telegram (+ кнопка «Следить»)
        │
        ▼
3. Мониторинг найденного аккаунта (бывший 10min.py)
   • раз в 10–30 минут, присылает только НОВЫЕ объявления
```

Уровни совпадения:

| | |
|---|---|
| 🎯 точное | имя совпало, все указанные плашки совпали |
| 🤔 возможное | имя похоже (OCR) или плашку не удалось прочитать со страницы |
| ↔️ то же имя, другие плашки | показывается только в итоговом отчёте |

## Установка (Windows)

1. **Python 3.9+** — https://www.python.org/downloads/ (при установке галочка «Add python.exe to PATH»).
2. **Библиотеки** — в папке с проектом:
   ```bash
   pip install -U -r requirements.txt
   ```
3. **Tesseract-OCR** (для скриншотов, см. ниже).
4. **Первый запуск** — скрипт сам спросит токен бота, chat_id и прокси и создаст `config.json`:
   ```bash
   python kleinanzeigen_bot.py
   ```
5. **Проверка всего сразу** (библиотеки, OCR, немецкий язык, токен, каждый прокси):
   ```bash
   python kleinanzeigen_bot.py --check
   ```

Повторить настройку: `python kleinanzeigen_bot.py --setup`. Проверка логики без сети: `--selftest`.

## OCR: установка Tesseract

Tesseract — бесплатная программа распознавания текста; бот вызывает её для скриншотов.

**Windows**
1. Открой https://github.com/UB-Mannheim/tesseract/wiki и скачай установщик
   `tesseract-ocr-w64-setup-5.x.x.exe` (64 bit).
2. Запусти. На шаге **Choose Components** раскрой **Additional language data (download)**
   и поставь галочку **German**. Остальное — по умолчанию.
3. Папку оставь стандартной: `C:\Program Files\Tesseract-OCR` — бот найдёт её сам.
   (Если поставил в другое место — впиши путь в `config.json`:
   `"tesseract_cmd": "D:\\Tools\\Tesseract-OCR\\tesseract.exe"`.)
4. Проверь: `python kleinanzeigen_bot.py --check` → в разделе «OCR» должны быть ✅
   «Tesseract 5.x», «языки: deu, eng» и «тестовый скрин распознан: Arne Schwarzmann…».

Если German при установке забыл: скачай файл
https://github.com/tesseract-ocr/tessdata_fast/raw/main/deu.traineddata и положи его в
`C:\Program Files\Tesseract-OCR\tessdata\`. Без немецкого OCR тоже работает (по-английски),
но умлауты распознаются хуже.

**macOS**: `brew install tesseract tesseract-lang`.
**Linux**: `sudo apt install tesseract-ocr tesseract-ocr-deu`.

На скриншотах профиля Tesseract распознаёт имя, дату, все плашки, подписчиков и счётчик
объявлений без ошибок (проверено на `tests/samples/screen_*.png`). Имя берётся как последняя
строка перед «N Anzeigen online»; инициалы аватарки и обрывки плашек игнорируются.
Перед поиском бот показывает карточку — любую ошибку можно поправить кнопками.

## Как пользоваться

После `/start` внизу появляется меню — всё управляется кнопками:

| Кнопка | Что делает |
|---|---|
| 🔍 Поиск по имени | пишешь только имя → дата выбирается кнопками (год → месяц → число) → плашки отмечаются кнопками → «🔍 Искать» |
| 📋 Задачи | текущий поиск: ⏸ пауза, ⏹ стоп, ▶️ продолжить, 🔁 перепроверить ошибки; очередь поисков |
| 📊 Статус | прогресс, сколько осталось, скорость, блокировки |
| 🏆 Результаты | последние поиски и найденные пользователи, кнопка «👁 Следить» |
| 👁 Мониторинг | кто отслеживается, проверить сейчас, удалить, ➕ добавить по ID/ссылке, интервал проверки |
| 🌐 Прокси | список прокси (пароли скрыты), ➕ добавить (можно несколько строкой), 🗑 удалить, 🧪 проверить, скорость |

📸 **Скриншот профиля можно прислать в любой момент** — бот распознает имя, дату и плашки
и покажет карточку, где всё исправляется кнопками. Текстом тоже можно:
`Manuela 08.02.2017 top, sehr freundlich`.

**Найденный аккаунт** сохраняется: в `config.json` → `found_accounts` (ID, имя, дата, плашки,
ссылка, когда найден) и `seed_anchors` (пара ID→дата), а также в базу якорей — следующие
поиски рядом с этой датой стартуют прямо от него.

## Скорость: прокси, потоки, несколько поисков

**Скорость ограничивает сайт, а не потоки.** Kleinanzeigen режет частые запросы с одного IP,
поэтому лимит `requests_per_second` действует на каждый прокси отдельно. Потоки (`workers`)
нужны только чтобы этот лимит реально выбрать: через прокси ответ идёт ~0.5–1.5 с, значит
при 10 запросах/с одновременно «в пути» 10–15 запросов. При `"workers": 0` (по умолчанию)
бот считает это сам: `лимит × число прокси × время ответа × 2`, максимум 64.

Замер на модели прокси (ответ 0.4–2 с, иногда зависание 6 с), лимит 10 запросов/с:

| Конфигурация | Скорость | День ≈25 тыс. ID |
|---|---|---|
| 1 прокси, 6 потоков (как было) | ~4.5 ID/с | ~90 мин |
| 1 прокси, потоки авто | ~9 ID/с | ~45 мин |
| 3 прокси, потоки авто | ~26 ID/с | ~16 мин |

Плюс поиск останавливается на первом точном совпадении — в среднем это половина дня.

Как ускорить:
- **Добавь прокси** (🌐 Прокси → ➕): каждый прокси — отдельный IP со своим лимитом,
  скорость складывается. Если один прокси заблокируют, на паузу уходит только он.
- **Лимит на прокси**: начни с 8–10/с. Если в «📊 Статус» нет блокировок — поднимай до 12–15.
  При блокировках бот сам делает паузу этому прокси и потом продолжает медленнее.
- **Кэш дня**: всё проверенное по дате хранится в `data/days/` 30 дней (`day_cache_days`).
  Повторный поиск по той же дате (другой человек того же дня, «Продолжить», перепроверка)
  не тратит запросы на уже проверенные ID.

**5 скриншотов сразу** — можно. Каждый станет карточкой; после «🔍 Искать» поиски встают
в очередь и идут по одному. Параллельно было бы не быстрее: все поиски делили бы тот же
лимит прокси, и каждый шёл бы в 5 раз медленнее — а по очереди первый результат приходит
в 5 раз раньше, а общее время то же. Если в очереди несколько человек с одной датой,
второй и следующие проверяются по кэшу дня почти мгновенно.

## Работа на сервере (VPS) 24/7

Хватает даже скромного VPS: 2 ядра, 4 ГБ, Windows 10. Бот почти всё время ждёт ответов сайта;
разбор одной страницы — ~25 мс процессора, память процесса — ~50–150 МБ (+ ~100–200 МБ на
время распознавания скриншота), кэш дня — около 1 МБ на дату.

- Запуск: двойной клик по `start_bot.bat` — если бот упадёт или сервер не ответит,
  он сам перезапустится через 30 с.
- Из RDP выходи **крестиком** (сеанс и бот продолжают работать), а не через «Выход».
- Автозапуск после перезагрузки (обновления Windows): `Win+R` → `shell:startup` → положи туда
  ярлык на `start_bot.bat` и включи автовход пользователя (`Win+R` → `netplwiz`).

## Файлы

`data/state.json` (поиск, очередь, история, мониторинг), `data/known_accounts.txt` (новые
якоря — пополняется при каждом поиске), `data/days/*.json` (кэш дней), `data/bot.log`.
База якорей `known_accounts` в репозитории (~160 пар «ID;дата» с 2009 по 2026) читается
при запуске: поиск диапазона дня занимает ~50–70 запросов.

## Что было сломано в старых скриптах и что исправлено

**Python.py (объединённый парсер)**
- `"proxy_url": socks5://...` без кавычек — `SyntaxError`, скрипт вообще не запускался,
  а вместе с ним падал и `Osnova.py` (он его импортировал). **Это и была поломка.**
- Этапы 1–2: ответ 403/503/таймаут считался «пользователя нет». При ограничении скорости
  бинарный поиск уходил не туда и границы дня получались неверными → нужный ID
  мог не попасть в диапазон. Теперь ошибки повторяются, «пусто» — только 404/пустая страница.
- Этап 1: фиксированная таблица шагов (700000/500000/25000/10000) могла «прыгать» вокруг
  даты все 300 попыток. Теперь шаг считается из реальной скорости регистраций.
- Этап 2: `MAX_REQUESTS=350` — при исчерпании лимита «доводка» возвращала случайную границу.
- Этап 3: ID, не успевшие за `batch_timeout`, помечались как проверенные — цель могла быть
  пропущена молча. Потоки после `shutdown(wait=False)` продолжали работать и превышали лимит.
- Этап 3: 404 (удалённые аккаунты) считались ошибками → ложные «слишком много ошибок».
- Сравнивалось только имя, плашки и дата не проверялись.
- Продолжение после остановки не работало: файл прогресса получал новое имя при каждом запуске.

**10min.py (мониторинг)**
- При первом запуске присылал ВСЕ объявления как «новые».
- Любая сетевая ошибка (`raise_for_status`) роняла скрипт навсегда.
- Если страница пришла пустой/капчей, список «виденных» обнулялся, и следующая проверка
  присылала всё заново. Теперь при ошибке список не трогается, а виденные объединяются.

**Ошибка `ValueError: invalid literal for int() … '8203Elbe…'`**
- Сайт пишет невидимый символ `&#8203` без `;` перед названием города. Старые
  beautifulsoup4 (<4.13) на этом падали, и одна такая страница роняла весь поиск.
  Теперь HTML очищается до разбора, а ошибка разбора одной страницы — это ошибка
  одного ID (перепроверится), а не всего поиска. Обнови: `pip install -U -r requirements.txt`.

**Osnova.py (бот)**
- Жёстко прописан путь `C:\Program Files\Tesseract-OCR\...`.
- Подтверждение — «продублируйте сообщение»; теперь кнопка «🔍 Искать».
- После каждого поиска бот «отдыхал» 5–15 минут и блокировал все команды (даже `/stop`).
  Теперь пауза включается только при реальной блокировке (много 403/429 подряд),
  а поиск сам продолжается после неё на пониженной скорости.

## Безопасность

Токены ботов и логин/пароль прокси были опубликованы в issues этого репозитория.
**Отзови токены** у @BotFather (`/revoke`) и **смени пароль прокси**. Новые храни только
в `config.json` (он в `.gitignore`) или в переменных окружения.

## Ограничения

- Мониторинг читает первую страницу `s-bestandsliste` (обычно ~25 последних объявлений) —
  новые объявления всегда наверху, поэтому этого достаточно.
- Счётчик «N Anzeigen online / M gesamt» сайт рисует JavaScript'ом — в HTML его нет,
  поэтому при сравнении он не используется (он и так меняется со временем).
- Если сайт поменяет вёрстку, проверь `parse_profile_html` — реальные страницы для теста
  лежат в `tests/samples/`: сохрани новую через `view-source:` и запусти `--selftest`.
