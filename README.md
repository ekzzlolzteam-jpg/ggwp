# Kleinanzeigen: поиск пользователя + мониторинг объявлений

Курсовая работа: поиск конкретного продавца на kleinanzeigen.de для анализа рынка.
Всё в **одном скрипте** `kleinanzeigen_bot.py` и **одном Telegram-боте**
(раньше это были 4 отдельных скрипта: `1.py`, `2v2.py`, `3neu.py`, `10min.py` + `Osnova.py`).

## Как это работает

```
скрин/текст в бота ──► распознавание ──► «🔍 Искать»
        │
        ▼
1. Поиск диапазона ID за нужный день (бывшие 1.py + 2v2.py)
   • старт — от ближайшей известной пары «ID → дата» (база якорей)
   • прыжки с оценкой «ID в день», которая уточняется по увиденным точкам
   • интерполяционный + бинарный поиск первой и последней границы дня
        │
        ▼
2. Перебор всех ID дня (бывший 3neu.py)
   • сравнение: имя (с учётом ä/ae/a и опечаток OCR), дата, плашки
   • точное совпадение → сразу сообщение в Telegram (+ кнопка «Следить»)
        │
        ▼
3. Мониторинг найденного аккаунта (бывший 10min.py)
   • раз в 10–30 минут, присылает только НОВЫЕ объявления
```

Уровни совпадения:

| | |
|---|---|
| 🎯 точное | имя совпало, все указанные плашки совпали |
| 🤔 возможное | имя похоже (OCR) или плашку не удалось прочитать со страницы |
| ↔️ то же имя, другие плашки | показывается только в итоговом отчёте |

## Установка

```bash
pip install -r requirements.txt
```

```bash
cp config.example.json config.json
```

В `config.json` впиши `telegram_token` (от @BotFather) и `allowed_chat_ids` (свой chat_id —
если оставить список пустым, бот сам пришлёт твой chat_id в ответ на любое сообщение).
Прокси — в `proxy_url` (в кавычках!), например `"socks5://user:pass@host:port"`.
Токен и прокси можно задать и переменными окружения `KA_TELEGRAM_TOKEN`, `KA_PROXY_URL`.

Для скриншотов нужен Tesseract-OCR с немецким языком
(Windows: установщик UB-Mannheim, галочка «German»). Путь находится автоматически,
иначе укажи `tesseract_cmd`. Без Tesseract бот работает с текстовым вводом.

## Запуск

```bash
python kleinanzeigen_bot.py
```

Проверка логики без сети и без Telegram:

```bash
python kleinanzeigen_bot.py --selftest
```

## Как пользоваться

Отправь боту скриншот профиля **или** текст в любом из форматов:

```
Имя: Manuela
Дата регистрации: 08.02.2017
Плашки: TOP Zufriedenheit, Besonders freundlich
```
```
Manuela
08.02.2017
top, sehr zuverlässig
```
```
Manuela 08.02.2017 naja
```

Плашки можно писать коротко: `top` / `ok` / `naja`, `sehr freundlich`, `besonders zuverlässig`.

| Команда | Что делает |
|---|---|
| `/status` | прогресс поиска, ошибки, мониторинг |
| `/pause` `/resume` `/stop` | управление поиском (прогресс сохраняется, `/resume` продолжает с места) |
| `/recheck` | перепроверить ID, которые не открылись |
| `/watch <id или ссылка>` | следить за новыми объявлениями любого профиля |
| `/unwatch <id>`, `/watchlist`, `/check` | управление мониторингом |
| `/anchor <id> <дд.мм.гггг>` | добавить известную пару «ID → дата» (ускоряет поиск) |

Файлы в `data/`: `state.json` (поиск, мониторинг), `known_accounts.txt` (база якорей —
пополняется автоматически при каждом поиске), `bot.log`.
Старый `known_accounts.txt` рядом со скриптом тоже подхватывается.

## Что было сломано в старых скриптах и что исправлено

**Python.py (объединённый парсер)**
- `"proxy_url": socks5://...` без кавычек — `SyntaxError`, скрипт вообще не запускался,
  а вместе с ним падал и `Osnova.py` (он его импортировал). **Это и была поломка.**
- Этапы 1–2: ответ 403/503/таймаут считался «пользователя нет». При ограничении скорости
  бинарный поиск уходил не туда и границы дня получались неверными → нужный ID
  мог не попасть в диапазон. Теперь ошибки повторяются, «пусто» — только 404/пустая страница.
- Этап 1: фиксированная таблица шагов (700000/500000/25000/10000) могла «прыгать» вокруг
  даты все 300 попыток. Теперь шаг считается из реальной скорости регистраций.
- Этап 2: `MAX_REQUESTS=350` — при исчерпании лимита «доводка» возвращала случайную границу.
- Этап 3: ID, не успевшие за `batch_timeout`, помечались как проверенные — цель могла быть
  пропущена молча. Потоки после `shutdown(wait=False)` продолжали работать и превышали лимит.
- Этап 3: 404 (удалённые аккаунты) считались ошибками → ложные «слишком много ошибок».
- Сравнивалось только имя, плашки и дата не проверялись.
- Продолжение после остановки не работало: файл прогресса получал новое имя при каждом запуске.

**10min.py (мониторинг)**
- При первом запуске присылал ВСЕ объявления как «новые».
- Любая сетевая ошибка (`raise_for_status`) роняла скрипт навсегда.
- Если страница пришла пустой/капчей, список «виденных» обнулялся, и следующая проверка
  присылала всё заново. Теперь при ошибке список не трогается, а виденные объединяются.

**Osnova.py (бот)**
- Жёстко прописан путь `C:\Program Files\Tesseract-OCR\...`.
- Подтверждение — «продублируйте сообщение»; теперь кнопка «🔍 Искать».
- После каждого поиска бот «отдыхал» 5–15 минут и блокировал все команды (даже `/stop`).
  Теперь пауза включается только при реальной блокировке (много 403/429 подряд),
  а поиск сам продолжается после неё на пониженной скорости.

## Безопасность

Токены ботов и логин/пароль прокси были опубликованы в issues этого репозитория.
**Отзови токены** у @BotFather (`/revoke`) и **смени пароль прокси**. Новые храни только
в `config.json` (он в `.gitignore`) или в переменных окружения.

## Ограничения

- Мониторинг читает первую страницу `s-bestandsliste` (обычно ~25 последних объявлений) —
  новые объявления всегда наверху, поэтому этого достаточно.
- Если сайт поменяет вёрстку, проверь `parse_profile_html` — тест с примером страницы
  лежит в `tests/test_bot.py`.
